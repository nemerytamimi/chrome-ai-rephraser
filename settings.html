Ollama (Local)

Run models locally with Ollama — no API key required.

⚠️ Required: Allow Chrome extension origin

Chrome extensions have a non-localhost origin (chrome-extension://…), which Ollama blocks by default (returns 403). You must start Ollama with the OLLAMA_ORIGINS environment variable set.

OLLAMA_ORIGINS=* ollama serve
launchctl setenv OLLAMA_ORIGINS "*"
# then restart Ollama from the menu bar
# In PowerShell (as admin):
[System.Environment]::SetEnvironmentVariable("OLLAMA_ORIGINS","*","User")
# then restart Ollama

Run ollama pull llama3.2 to download a model. Other options: mistral, gemma3, phi4, qwen2.5.

LM Studio

Run any GGUF model locally via LM Studio's built-in server.

⚠️ Required: Enable CORS in LM Studio

Chrome extensions send a non-localhost Origin header, which LM Studio blocks by default. Enable cross-origin requests before using this provider:

  1. Open LM Studio and start a model
  2. Go to the Local Server tab (↔ icon in the left sidebar)
  3. Enable "Allow requests from any origin (CORS)"
  4. Click Start Server

Default is http://localhost:1234. Change only if you've set a custom port in LM Studio.

LM Studio accepts any string here — it always uses the currently loaded model. You can leave this as local-model.

MCP Integration

Connect to any Model Context Protocol compatible server.

The MCP tool name to call. The extension sends the prompt as arguments.text.

MCP Protocol Info

This extension communicates with MCP servers over HTTP using JSON-RPC 2.0. Your server must expose a POST endpoint that accepts:

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "<tool-name>",
    "arguments": { "text": "<prompt>" }
  }
}

And return a standard MCP response with result.content.
